# SENDA.V0 0.4.4 Consolidación Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar una SENDA 0.4.4 donde escritorio y GitHub compartan la misma UI y se cumplan carga, NUMERO=FOLIO, copia, selección de movimientos, Gestión, enlaces, sincronización y build Windows.

**Architecture:** La UI oficial será `ui/`, servida por el servidor local y embebida en una ventana WebView de Windows. SQLite seguirá siendo la fuente local; se agregan tablas/campos aditivos para selección de movimientos, estado de Gestión, enlaces y referencias de cédulas jurídicas.

**Tech Stack:** Python 3.12, SQLite, HTTP local, HTML/CSS/JS, pywebview, PyInstaller, openpyxl/xlsxwriter/xlrd por pip.

**Spec:** Requisitos consolidados del proyecto SENDA aprobados en conversación.

## Global Constraints
- `NUMERO` es autoritativo para FOLIO/FINCA.
- XLS/XLSX/CSV/JSON/TXT/ZIP/RAR deben cargar sin convertir auxiliares en movimientos.
- GitHub UI y Windows deben usar los mismos archivos `ui/`.
- No usar copias locales de openpyxl/xlsxwriter/et_xmlfile.
- No finalizar Control sin movimientos seleccionados.
- Gestión exporta solo los movimientos seleccionados.
- Importar bases fusionables no borra datos existentes.
