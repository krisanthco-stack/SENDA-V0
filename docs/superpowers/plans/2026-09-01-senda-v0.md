# SENDA.V0 Implementation Plan

> **For agentic workers:** implement task-by-task with TDD and fresh verification.

**Goal:** Build a new local Windows SENDA.V0 application with a compact horizontal UI, four modules, large-file streaming imports, quarterly/district classification, prior alarm rules, SQLite persistence, exports, and robust install/update/uninstall launchers.

**Architecture:** Python standard-library HTTP server and SQLite backend, modular import pipeline, static single-page horizontal UI, and Windows batch/PowerShell launchers. User data lives outside replaceable application code. Importers detect content plus headers and stream rows into SQLite in batches.

**Tech Stack:** Python 3.10+, sqlite3, csv/json/zipfile, optional openpyxl for XLSX, internal OLE/BIFF reader for legacy XLS, optional rarfile/unrar for RAR, vanilla HTML/CSS/JS, PowerShell/batch.

**Spec:** Approved chat design: preserve prior horizontal structure, max four modules, quarterly T1–T4, month/year/district/alarm filters, alarm thresholds red >=90 days and yellow >60 days, support real XLS/XLSX/CSV/JSON/TXT/ZIP/RAR, no artificial upload-size limit.

## Global Constraints
- Four primary modules maximum: Inicio, Información SENDA/Control, Expedientes, Configuración.
- Horizontal desktop-first layout, compact visual density.
- Application code and user data must be separated.
- No silent launcher exit on server failure.
- Streaming/batched imports; no full-file browser buffering.
- Preserve source district and quarter metadata for every imported movement.
